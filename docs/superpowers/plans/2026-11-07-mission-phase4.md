# Phase 4 — bounded scheduling above the existing graph

**Baseline:**348ce7c,631 passed/3 native skipped in81.16s. Phases2/3 Windows gates pending.
**Spec:** supplied CODEX_MONSTER_V3_PHASE4_PROMPT.md and existing v3 docs.

## Design

Add a versioned scheduling envelope around v1 Mission, not a second graph/store.
Schema4 stores immutable plan digest, exact orchestration consent, aggregate counters,
reservations and progress events. Existing graph nodes consult the scheduler only
for admitted Phase4 plans; earlier missions keep their semantics. Reserve the full
bounded subtask envelope before dispatch, settle from authoritative counts/cleanup,
charge unknown reservations conservatively across crash. This may stop earlier than
a fine-grained counter but cannot grant extra native actions/planning calls.

Six fixed editor objectives; default simulation and observe-only rehearsal. Live
pilot requires explicit reviewed Phase2+3 qualification metadata and experimental
opt-in; nothing is qualified by this implementation. Mission consent permits outer
sequence only, never action/effect approvals. No new input path/provider/framework.

Boundary pause lets the current bounded subtask finish, then invalidates consent
and generation before the next task. Immediate stop retains existing cancellation.
Fresh consent/provider binding, effect reconciliation and scene preflight gate resume.
Pure retry is simulation-only/pre-dispatch and bounded; a GUI handoff is never retried.
