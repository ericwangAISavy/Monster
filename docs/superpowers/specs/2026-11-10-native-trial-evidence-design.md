# V4 stage 4: per-attempt native draft evidence

User authorized the next implementation inline. Actual Windows qualification is
unavailable on this Linux executor. Implement the portable evidence-assessment
slice; do not claim native success or enable step 5.

The existing native record records aggregate checks, not traceable repeated
attempts. Add a read-only module that combines the existing `assess_native`
result with a strict per-attempt manifest and existing explicitly exported JSON
run reports. Prefer this over another executor, scheduler, ledger or GUI wizard.
No controller/policy changes, new dependencies or default persistence.

Fixed protocol: the documented unsent Slack draft instruction; focused/unfocused
composer × approval true/false; three attempts per case by default (bounded
1–20 configurable sample size, not a statistical release guarantee). Template
leaves observations and report references unknown. Human observations establish
visible exact text, intended field, unsent state, one insertion, duplicate and
wrong-target counts, interventions/recovery and any requested stop/held-input
cleanup. Model success and accepted input alone cannot establish success.

Bind bounded local JSON reports by SHA-256 and unique run ID; reject path escapes,
duplicates, malformed/unknown manifest fields, changed source/model/configuration,
wrong task/policy, running/pending reports and missing worker provenance. Failed
and unknown trials remain in denominators and block advisory review eligibility.
Model/provider/tool/executor/host failure attribution is explicitly operator
reported or unknown; do not guess from free-text errors. Preserve independent
native tool checks through the existing assessor. Export fixed categories,
references, counts and operation-wait totals only; never copy report task text,
images, raw evidence or exceptions. Full run exports may contain private content:
read locally only and do not automatically persist/copy them.

Output is an advisory, operator-reported inventory, never an execution grant,
authenticity proof or machine qualification. Synthetic tests can exercise a
consistent Windows-shaped record but must remain labelled synthetic evidence in
test documentation. Next real work: live model benchmark and Windows protocol.
