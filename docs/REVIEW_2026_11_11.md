# Reliability review and repairs — 2026-11-11

Baseline: `950b6a6` on `work`. The user requested a whole-agent review and fixes.
Three read-only domain reviews and a parent review inspected the major subsystem
boundaries. This is source review plus portable regression testing, not a formal
proof that every path is correct or native/model qualification.

## Reproducible issues repaired

1. **Hands-free settings could not save after a successful compatibility check.**
   The check used default hands_free=false while Save compared against the selected
   true value. A single compatibility projection now normalizes mode, per-step
   review and hands-free policy in initial cache, check configuration and Save.
   Actual inference/endpoint changes still invalidate the check. Runtime policy
   itself is not relaxed.
2. **The settings dialog accepted negative/wrong-model probe results as success.**
   Its callback cached every error-free object before validating its evidence,
   and None/True could raise during status rendering. It now uses the existing
   strict positive compatibility contract before completed logging or caching.
   Invalid results produce a fixed failure, with no cache or save authorization.
3. **The second click of a double-click could hit a different target after takeover.**
   Physical arrival was checked only before the loop. The second mouse-down now
   rechecks the authorized position after the inter-click wait. Detected takeover
   disarms with partial/unknown status and owned-input cleanup; it never steers
   back or replays. Stable double-clicks retain two complete clicks. A movement
   after the final cursor sample remains subject to native timing limitations;
   this fix does not claim atomic OS-level pointer/SendInput behavior.
4. **Historical guest stop confirmation masked resumed work and session changes.**
   A successful authenticated new challenge/accepted execution cycle now clears
   the old stop confirmation. Refused work retains it. Current session/display/
   provider/restore/clock requalification reasons take precedence over historical
   stop text. This changes host projection only, not guest permissions or consent.
